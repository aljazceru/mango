<objective>
Add DEK-based encryption to VectorIndex save/load. The usearch index is serialized to bytes,
encrypted with AES-256-GCM via crypto::file_crypto, and written to disk. On load, detect
MGO1 magic header to distinguish encrypted from legacy unencrypted files.

Purpose: Protect vector embeddings at rest (per D-02). Without this, memory/RAG embeddings
are readable on disk even though the SQLite DB is encrypted.

Output: Updated rag/index.rs with encrypted save/load and automatic legacy migration.
</objective>

    Change VectorIndex to accept an optional DEK for encrypted operation:

    **VectorIndex::new signature change:**
    `pub fn new(data_dir: &str, dek: Option<&[u8; 32]>) -> anyhow::Result<Self>`

    On load: read file bytes. Check first 4 bytes for `b"MGO1"`:
    - If MGO1 present and dek is Some: decrypt with `crypto::file_crypto::decrypt_file`, then load from decrypted bytes using usearch's `Index::load()` from a temp file (usearch only supports file-path loading, so write decrypted bytes to a temp file, load, delete temp file).
    - If MGO1 NOT present (legacy unencrypted): load directly from path as before.
    - If MGO1 present and dek is None: return error (encrypted file but no key).

    **VectorIndex::save signature change:**
    `pub fn save(&self, dek: Option<&[u8; 32]>) -> anyhow::Result<()>`

    On save: if dek is Some, save index to a temp file, read bytes back, encrypt with `encrypt_file`, write encrypted bytes to `self.path`. If dek is None, save directly (backwards-compatible for tests).

    **Update all call sites** in lib.rs: pass `dek` from ActorState when calling `VectorIndex::new()` and `save()`. Before Plan 02 is executed, these call sites pass `None`. After Plan 02 wires the DEK, they pass `Some(&dek)`. For now, ensure the signature accepts Option so both work.
