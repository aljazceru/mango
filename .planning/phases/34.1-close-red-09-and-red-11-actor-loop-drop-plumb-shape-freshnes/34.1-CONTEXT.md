**This phase closes that gap.** Wire shape/freshness/orchestrated_components from `AttestationEvent::Verified` through:
1. The actor-loop destructure (stop dropping; thread the values).
2. The UniFFI `AttestationStatus` boundary (extend Verified with optional sub-fields, OR add a parallel UniFFI struct keyed by backend_id — implementation decision, see below).
3. The `AttestationRecord` SQLite cache so re-hydrated attestation status survives app restart.
4. Native trust UI rendering on Android (and iOS/desktop where renderers exist).

**Out of scope:** Any change to the cryptographic verification path; any new attestation shapes; Redpill→Tinfoil routing (still unsupported). The verification logic stays exactly as it is.

- Failed/Expired/Unverified branches do not carry these fields — they remain `None`/absent.

### UniFFI boundary (Claude's Discretion — recommended approach)
- **Recommended:** Add additive optional fields to `AttestationStatus::Verified` so the existing variant becomes `Verified { shape: Option<String>, freshness: Option<String>, orchestrated_components: Option<Vec<UniFfiOrchestratedComponent>> }` (since `Verified` is currently unit-like, this means promoting it to a struct variant). UniFFI supports struct variants; the change is additive at the wire level for the variants that existed.
- **Alternative considered:** Add a parallel `AttestationDetail` UniFFI struct keyed by backend_id and exposed alongside `AttestationStatus`. Rejected as default because it duplicates the carrier and forces native UIs to correlate two collections.
- **Rationale:** The natives already pattern-match on `AttestationStatus`. Extending `Verified` keeps the renderer site singular.

### Persistence (LOCKED)
- Extend `AttestationRecord` (struct + the `attestation_cache` SQLite table) with three nullable columns: `shape TEXT NULL`, `freshness TEXT NULL`, `orchestrated_components TEXT NULL` (JSON-encoded `Vec<(String, String)>`).
- Add an additive ALTER TABLE migration; do not break existing cache rows. Re-hydration must populate `AttestationStatus::Verified { shape, freshness, orchestrated_components }` from the columns.

## Specific Ideas

- The exact destructure that needs editing is rust/src/lib.rs lines 7414-7430. The fields currently read `shape: _, freshness: _, orchestrated_components: _`.
- The data shape for orchestrated_components on the wire is `Vec<(String, String)>` where the first string is one of `"gateway" | "model" | "compose_manager"` and the second is the hex address/actions hash.
- For UniFFI, `Vec<(String, String)>` is not directly representable — wrap as `Vec<UniFfiOrchestratedComponent { label: String, value: String }>` (UniFFI struct).
- Freshness values today: only `"PerRequest"` and `"PerEnclave"` strings. Treat as opaque on the UI side (string match).
- AppState already carries `attestation_statuses: Vec<(backend_id, AttestationStatus)>` — extend by replacing `Verified` with the struct variant; native code will see it as a richer enum.
</specifics>
