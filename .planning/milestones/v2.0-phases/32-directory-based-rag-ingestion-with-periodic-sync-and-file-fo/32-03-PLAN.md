    - Set `app_state.ingestion_progress = Some(IngestionProgress { filename: "Syncing directory".into(), ...})` and emit state.
    - For each `DirectoryFileEntry` in `files` (up to 50 per batch):
      1. Extract text via existing `chunker::extract_text_from_bytes` (or the doc-text extractor used by IngestDocument).

      5. Embed chunks via `embedding_provider.embed_batch(...)`.
      6. usearch `add()` each (rowid, vector); keys are chunk rowids (same keyspace as existing).
      7. `upsert_directory_file(conn, source_id, &entry.relative_path, entry.mtime_secs, entry.size_bytes, Some(document_id))`.
      8. If a previous document_id existed for this (source_id, file_path) — i.e. this is a "modified" replay — first delete the old document + chunks + usearch keys before inserting new. Use existing single-doc delete helper.

      1. Look up `directory_files` row to get `document_id`.
      2. Call existing `delete_document` helper (cascades chunks + usearch keys).

    **RemoveDirectorySource handler (DIR-06):**
    - List all `directory_files` for source_id.
    - For each row with `document_id`, call `delete_document` (cascades chunks + usearch keys).
    - Call `delete_directory_source` (SQLite FK cascades `directory_files` rows automatically).
    - Reload summaries.

    **SetDirectoryExclusions handler:**
    - Validate each glob with `directory_sync::validate_glob_pattern`.
    - If any invalid: set `app_state.error_message`, abort without writing.

    - Call `update_directory_source_bookmark(conn, source_id, &bookmark_data)`.
    - No AppState reload needed (bookmark is opaque, not part of summary).

    - Set `sync_status = Syncing` for that source summary; emit state.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Native→AppAction | DirectoryFileEntry content bytes arrive from native file reads; length checked implicitly by extract_text bounds |
| User→exclusion_globs | Re-validated in SetDirectoryExclusions handler before persistence |
| Native→bookmark_data | Opaque BLOB; never parsed in Rust (iOS SDK opaque token) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-32-V4 | Access Control | SyncDirectoryFiles handler | accept | Reads are scoped to bytes already supplied by native layer inside its security-scoped resource; Rust never opens paths on its own on mobile |
| T-32-V5 | Input Validation | AddDirectorySource + SetDirectoryExclusions glob inputs | mitigate | `validate_glob_pattern` via globset rejects malformed patterns before persistence; error surfaced to UI via `app_state.error_message` |
| T-32-V6 | Cryptography | VectorIndex.save after batch | mitigate | Uses existing DEK from ActorState (Phase 29 — ENC-02); new artifacts inherit encrypted-at-rest posture automatically (D-37) |
| T-32-DoS1 | Denial of Service | SyncDirectoryFiles memory | mitigate | Hard batch ceiling enforced at 50 entries per AppAction (D-25); VectorIndex flushed per batch to bound memory growth (D-27) |
| T-32-I2 | Information Disclosure | DirectorySourceSummary exposed over UniFFI | accept | Summary contains only user-visible labels/counts; bookmark_data and tree_uri stay in SQLite, never in AppState |
</threat_model>
