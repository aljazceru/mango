  <action>
    On app startup, spawn:

    **Watcher thread** (one `RecommendedWatcher` managing one `notify_debouncer_mini::Debouncer`):
    - For each existing `DirectorySourceSummary` with a Desktop `path`, add to watcher via `watch(&path, RecursiveMode::Recursive)`.
    - Debounce 2s (per D-10).
    - On event batch: send `AppAction::TriggerDirectorySync { source_id }` via flume.
    - If `RecommendedWatcher::new` or `watch()` returns Err matching ENOSPC / watch-limit, rebuild with `PollWatcher::new(config.with_poll_interval(Duration::from_secs(60)))` and emit `Message::WatcherFallbackWarning(Some("File watching unavailable; syncing on schedule every 5 min"))`.

    **5-minute Tokio interval** (fallback per D-21):
    ```rust
    tokio::spawn(async move {
        let mut ticker = tokio::time::interval(Duration::from_secs(300));
        loop {
            ticker.tick().await;
            for source in current_sources() {
                tx.send(AppAction::TriggerDirectorySync { source_id: source.id.clone() });
            }
        }
    });
    ```

    **Walker pipeline** — helper `run_desktop_sync(source_id, path, globs, stored_fingerprints, tx)`:
    1. Call `mango_core::rag::directory_sync::walk_with_exclusions(&path, &globs)?` → `Vec<(String, i64, i64)>`.
    2. Fetch stored fingerprints for this source (via a new read-only AppAction `QueryDirectoryFingerprints { source_id }` → AppState field, OR use a direct `mango_core` helper exposed by Plan 03 that reads from SQLite without going through the actor — prefer the actor path for single source of truth).
    3. Call `diff_files(&stored, &current)` → `FileDiff`.
    4. For each batch of 50 in `diff.added` ++ `diff.modified`:
       - Read file bytes (`std::fs::read(&path)`).
       - Build `Vec<DirectoryFileEntry>`.
       - Dispatch `AppAction::SyncDirectoryFiles { source_id, files: batch, removed_paths: (first-batch only) diff.removed.clone(), is_final_batch: is_last }`.
       - Wait for the actor to acknowledge via state emission (watch `ingestion_progress` returning to None, or use a completion channel).
    5. If `added+modified` empty but `removed` non-empty: dispatch one SyncDirectoryFiles with empty files + removed_paths + is_final_batch=true.

    TriggerDirectorySync state handling: subscribe to AppState changes; when a source flips to `sync_status: Syncing`, run `run_desktop_sync` on a dedicated tokio task (not the actor thread).
  </action>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Filesystem→app | Files at user-chosen path are read by `std::fs::read` |
| FS events→watcher | notify events fed into TriggerDirectorySync — could be spammed by malicious FS activity |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-32-V4 | Access Control | walk_with_exclusions root path | accept | Root is only a path the user picked via rfd; no privilege escalation |
| T-32-DoS1 | Denial of Service | notify watcher event burst | mitigate | 2-second debounce collapses bursts (D-10); 50-file batching caps memory (D-25) |
| T-32-DoS2 | Denial of Service | inotify watch limit exhaustion | mitigate | Catch ENOSPC, fall back to PollWatcher(60s) + surface UI warning (D-11) |
</threat_model>
