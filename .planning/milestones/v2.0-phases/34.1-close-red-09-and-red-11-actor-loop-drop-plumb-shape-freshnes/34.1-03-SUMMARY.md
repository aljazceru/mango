# Phase 34.1 Plan 03: SQLite V19 Cache Persistence Summary

**One-liner:** Add MIGRATION_V19 (three nullable TEXT columns on `attestation_cache`) and extend `AttestationCache::{put,get,get_latest_for_backend}` to round-trip Redpill `shape`/`freshness`/`orchestrated_components` across app restarts, with backward-compat for pre-V19 rows.

## What Was Done

1. **Task 1 (commit `cbe9dc4`)** — Added `pub const MIGRATION_V19` containing three `ALTER TABLE attestation_cache ADD COLUMN ... TEXT` statements (`shape`, `freshness`, `orchestrated_components`). Appended to `MIGRATIONS` array. Added `test_migration_v19_adds_three_columns` asserting all three columns appear in `PRAGMA table_info`.

2. **Task 2 (commit `5d07a47`)** — Extended `AttestationCache` CRUD:
   - `put`: 9-column INSERT OR REPLACE; binds `record.shape.as_deref()`, `record.freshness.as_deref()`, and `serde_json::to_string(&components_tuple_vec).ok()`.
   - `get` + `get_latest_for_backend`: SELECT extended with three new columns; row-mapper reads `shape`/`freshness` as `Option<String>` and `orchestrated_components` as JSON-decoded `Option<Vec<(String, String)>>` with `.ok()` fallback to `None`.
   - For verified rows (status string `"verified"` or `"provider_verified"`), construct `AttestationStatus::Verified { shape, freshness, orchestrated_components }` directly from columns (converting tuple pairs to `Vec<OrchestratedComponent>`). For non-verified rows, fall back to `deserialize_status` as before.
   - Added `OrchestratedComponent` import; `serde_json` was already in scope via the workspace.
   - Added a comment on `deserialize_status` clarifying it's the non-row-mapper fallback.

3. **Task 3 (commit `5bc2284`)** — Added two new tests:
   - `attestation_cache_v19_round_trip`: builds an `AttestationRecord` with `shape: Some("Orchestrated")`, `freshness: Some("PerRequest")`, three orchestrated components (gateway/0xAA, model/0xBB, compose_manager/0xCC). Calls `put` then `get_latest_for_backend`; asserts byte-for-byte preservation of all three fields and that `status` matches `Verified` with the same subfields populated.
   - `cache_pre_v19_row_returns_none_subfields`: directly INSERTs a legacy 6-column row (status `"verified"`, NULL for the new columns). Asserts `record.shape.is_none()`, `record.freshness.is_none()`, `record.orchestrated_components.is_none()`, and that `status` matches `Verified { shape: None, freshness: None, orchestrated_components: None }`.
   - Also bumped pre-existing user_version assertions in `tests/persistence.rs` (3 sites) and `tests/rag.rs` (1 site) from `18` to `19` — these were broken by the legitimate addition of MIGRATION_V19.

## Deviations from Plan

**1. [Rule 1 — Bug] Bumped 4 pre-existing `user_version` assertions from 18 to 19.**
- **Found during:** Task 3 (full lib suite run).
- **Issue:** `test_migration_v1_to_v2`, `test_migration_idempotent`, `test_migration_version_increments`, `test_migration_v6_version`, `test_migration_v11_seeds_ppq_ai_private_transport` all hardcoded `version == 18`. Adding MIGRATION_V19 legitimately bumps the schema version to 19, which is the correct outcome — the failing assertions were the bug.
- **Fix:** Changed the 4 magic-number sites and accompanying message strings to `19`.
- **Files modified:** `rust/src/tests/persistence.rs`, `rust/src/tests/rag.rs`.
- **Commit:** `5bc2284`.

**2. [Plan note] `get_latest_for_backend` signature unchanged.**
The plan's example test code called `cache.get_latest_for_backend("redpill-test", 1_700_000_100)` (two args), but the actual function takes one arg and uses `SystemTime::now()` internally. Test fixtures use `now + 3600` for `expires_at` so the real-time TTL filter passes. No code change needed — the plan's two-arg form was illustrative.
