# Phase 34.1 Plan 02: Promote AttestationStatus::Verified to struct variant + regenerate bindings

**One-liner:** Promote `AttestationStatus::Verified` to a uniffi struct variant carrying optional `shape`/`freshness`/`Vec<OrchestratedComponent>`, sweep ~14 Rust call sites with the compiler, and regenerate Kotlin + Swift bindings so native UIs can read the threaded Redpill diagnostics.

## What Was Done

1. **Task 1 (commit `d1017f8`)** — Added `pub struct OrchestratedComponent { label, value }` with `#[derive(uniffi::Record, Clone, Debug, PartialEq)]` placed above `AttestationStatus`. Promoted `AttestationStatus::Verified` from unit to struct variant `{ shape: Option<String>, freshness: Option<String>, orchestrated_components: Option<Vec<OrchestratedComponent>> }`. Updated `map_event_to_record_and_status` to build a single `status_uniffi` binding (converts tuple Vec → `Vec<OrchestratedComponent>`) and reuse it for both `record.status` and the outer return — keeps the record self-consistent with its parallel `shape`/`freshness`/`orchestrated_components` columns.

2. **Task 2 (commit `e0d9f0d`)** — Compile-driven sweep. Updated:
   - `rust/src/attestation/cache.rs` — `serialize_status` match arm becomes `Verified { .. }`; `deserialize_status` fallback constructs `Verified { shape: None, freshness: None, orchestrated_components: None }` with a comment noting row-mapper paths in 34.1-03 will populate from columns.
   - `rust/src/lib.rs` (lines 7432, 7436) — both actor-loop match arms gain `{ .. }`.
   - `rust/src/tests/attestation_types.rs`, `attestation_cache.rs`, `attestation_integration.rs` — every test fixture constructing `Verified` now uses the struct-variant form with `None` defaults.
   - `rust/src/tests/live_tinfoil.rs:194` — pattern match arm now `Verified { .. } =>`.
   - `rust/src/tests/redpill.rs` (the 34.1-01 test) — `matches!(status, AttestationStatus::Verified { .. })`.

3. **Task 3 (commit `1758c06`)** — Added `attestation_status_verified_carries_redpill_fields` test exercising the new variant directly with three orchestrated components, then regenerated bindings via `just bindings-kotlin` and `just bindings-swift`. Both `android/app/src/main/java/dev/disobey/mango/rust/mango_core.kt` and `ios/Bindings/mango_core.swift` now expose `OrchestratedComponent` and the three new fields on `AttestationStatus.Verified`.
