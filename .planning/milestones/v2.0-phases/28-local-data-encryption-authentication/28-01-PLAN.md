    ```rust
    pub fn open_encrypted(path: &str, dek_hex: &str) -> Result<Self, PersistenceError> {
        let conn = rusqlite::Connection::open(path)?;
        // CRITICAL: key pragma MUST be first operation after open (per D-01)
        conn.pragma_update(None, "key", &format!("x'{}'", dek_hex))?;
        conn.pragma_update(None, "journal_mode", "WAL")?;
        conn.pragma_update(None, "foreign_keys", "ON")?;
        let mut db = Self { conn };
        db.run_migrations()?;
        Ok(db)
    }
    ```

    Add `is_encrypted` static method:
    ```rust
    pub fn is_encrypted(path: &str) -> bool {
        let Ok(conn) = rusqlite::Connection::open(path) else { return false; };
        // If we can read user_version without a key, DB is plaintext
        conn.pragma_query_value::<i32, _, _>(None, "user_version", |r| r.get(0)).is_err()
    }
    ```

    Add `migrate_to_encrypted` static method:
    ```rust
    pub fn migrate_to_encrypted(path: &str, dek_hex: &str) -> Result<(), PersistenceError> {
        let enc_path = format!("{}_enc", path);
        let conn = rusqlite::Connection::open(path)?;
        conn.pragma_update(None, "journal_mode", "WAL")?;
        conn.execute_batch(&format!(
            "ATTACH DATABASE '{}' AS encrypted KEY \"x'{}'\"; SELECT sqlcipher_export('encrypted'); DETACH DATABASE encrypted;",
            enc_path, dek_hex
        ))?;
        drop(conn);
        // Verify encrypted DB opens correctly before replacing
        let verify = Self::open_encrypted(&enc_path, dek_hex)?;
        drop(verify);
        std::fs::rename(&enc_path, path).map_err(|e| PersistenceError::MigrationFailed {
            version: 0,
            message: format!("rename after encryption: {}", e),
        })?;
        Ok(())
    }
    ```

    Add a new `PersistenceError` variant if needed: `DecryptionFailed { message: String }`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PIN input -> Argon2id | Untrusted user input used as KDF input |
| DEK in memory | Decrypted key material lives in process memory |
| Bootstrap DB on disk | Unencrypted file containing salt and wrapped DEK |
| File system | Encrypted files on disk could be copied/tampered |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-28-01 | Tampering | bootstrap_db.rs | mitigate | AES-256-GCM tag on wrapped_dek detects tampering; any modification causes unwrap failure |
| T-28-02 | Information Disclosure | key_derivation.rs | mitigate | Use `zeroize::Zeroizing` wrapper on all intermediate key buffers; DEK and KEK zeroized on drop |
| T-28-03 | Information Disclosure | persistence/mod.rs | mitigate | SQLCipher key pragma issued as first operation; WAL journal also encrypted by SQLCipher |
| T-28-04 | Denial of Service | key_derivation.rs | accept | Argon2id with 64MiB memory is intentionally slow (~0.5s); this is the security tradeoff |
| T-28-05 | Tampering | file_crypto.rs | mitigate | GCM authentication tag (16 bytes) detects any ciphertext modification |
| T-28-06 | Repudiation | bootstrap_db.rs | accept | No audit log of failed PIN attempts in v1; low risk for single-user app |
| T-28-07 | Information Disclosure | file_crypto.rs | mitigate | Fresh random nonce per encrypt operation via OsRng; no nonce reuse possible |
| T-28-08 | Elevation of Privilege | persistence/mod.rs | mitigate | migrate_to_encrypted verifies new DB opens correctly before renaming; crash recovery deletes incomplete export |
</threat_model>
