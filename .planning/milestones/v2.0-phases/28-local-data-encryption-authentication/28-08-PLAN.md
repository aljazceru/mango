Replace the entire `BiometricResult` handler block (currently at line 5517-5534 of rust/src/lib.rs) with the following logic:

```rust
llm::InternalEvent::BiometricResult { success } => {
    if success {
        // Per D-06 / ENC-09: biometric success loads DEK from keychain
        // and opens the encrypted DB without requiring PIN entry.
        let maybe_dek_hex = actor_state.keychain.load(
            "mango".to_string(),
            "dek".to_string(),
        );
        if let Some(dek_hex) = maybe_dek_hex {
            log::info!("[auth] Biometric unlock: DEK loaded from keychain — opening DB");
            if actor_state.db_path == ":memory:" {
                if let Ok(db) = persistence::Database::open(":memory:") {
                    actor_state.db = Some(db);
                }
            } else {
                match persistence::Database::open_encrypted(
                    &actor_state.db_path,
                    &dek_hex,
                ) {
                    Ok(db) => {
                        actor_state.db = Some(db);
                    }
                    Err(e) => {
                        log::error!("[auth] Biometric unlock: open_encrypted failed: {e}");
                        actor_state.app_state.toast = Some(
                            "Biometric unlock failed: database error. Try PIN.".to_string(),
                        );
                        actor_state.app_state.biometric_authenticated = true;
                        actor_state.app_state.rev += 1;
                        emit(&actor_state.app_state, &shared_for_core, &update_tx);
                        continue;
                    }
                }
            }
            actor_state.app_state.encryption_enabled =
                actor_state.db_path != ":memory:";
            load_post_unlock(
                &mut actor_state,
                core_tx_for_thread.clone(),
                true,
            );
            // load_post_unlock already calls emit, so skip the emit below.
            continue;
        } else {
            // No DEK in keychain (biometric was not enabled during setup,
            // or keychain was cleared). Fall back to PIN input.
            log::info!("[auth] Biometric succeeded but no DEK in keychain — falling back to PIN");
            actor_state.app_state.biometric_authenticated = true;
        }
    } else {
        actor_state.app_state.toast =
            Some("Biometric authentication failed.".to_string());
    }
    actor_state.app_state.rev += 1;
    emit(&actor_state.app_state, &shared_for_core, &update_tx);
}
```

Key design decisions in this implementation:
- Follows the exact same DB open pattern as UnlockWithDek (lines 4381-4404) and UnlockWithPin (lines 4497-4511)
- On open_encrypted failure, sets biometric_authenticated=true so user can fall back to PIN entry (graceful degradation per D-24)
- If keychain returns None (DEK was never stored — e.g., user did not enable biometric during setup), falls back to the existing PIN-prompt behavior
- Uses `continue` after load_post_unlock to skip the trailing emit (load_post_unlock already emits)
- The loaded dek_hex is a plain String (not Zeroizing) because keychain.load returns Option<String>. This is acceptable because the DEK hex lives briefly on the stack and is dropped at block end.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Keychain read/write | DEK hex crosses from Rust actor to platform keychain and back; keychain is trusted hardware-backed storage |
| Biometric result | BiometricProvider returns success/failure from platform biometric hardware; result trusted as it comes from OS API |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-28-GC-01 | Spoofing | BiometricResult success path | mitigate | BiometricResult is dispatched only from the spawn_blocking task that calls biometric_provider.authenticate() — cannot be forged by external actors. The InternalEvent channel is internal to the actor. |
| T-28-GC-02 | Information Disclosure | DEK hex in keychain | accept | DEK stored in platform keychain which is hardware-backed (Secure Enclave on iOS, StrongBox on Android). This is the design intent per D-05/D-06. The keychain is the secure storage mechanism. |
| T-28-GC-03 | Elevation of Privilege | Biometric fallback to PIN | mitigate | When keychain.load returns None, handler falls back to PIN input (biometric_authenticated=true only reveals PIN field). No auth bypass — user must still provide valid PIN. |
| T-28-GC-04 | Information Disclosure | DEK hex briefly on stack in BiometricResult | accept | The String returned by keychain.load lives on the stack for the duration of the match block and is dropped at block exit. Brief exposure is acceptable — the same pattern is used in UnlockWithPin for the derived DEK hex. |
