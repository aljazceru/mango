## Spacing Scale

Declared values (must be multiples of 4). Extrapolated from existing padding patterns in `OnboardingScreen.kt` and `OnboardingView.swift`.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px / 4dp | Icon gaps, dot indicator spacing, inline element gaps |
| sm | 8px / 8dp | Between PIN digit cells, progress dot spacing, button row gaps |
| md | 16px / 16dp | Default element spacing within a form section |
| lg | 24px / 24dp | Horizontal screen padding (established pattern: `padding(horizontal = 24.dp)`) |
| xl | 32px / 32dp | Top padding from safe area, section breaks |
| 2xl | 48px / 48dp | Top padding for lock screen centered content |
| 3xl | 64px / 64dp | Page-level vertical centering offset |

Exceptions:
- PIN digit cells: 44px minimum touch target (WCAG 2.5.5) — each cell is 52x64dp on Android, 52x64pt on iOS, width(52)/height(64) on Desktop
- Biometric button: 64x64dp/pt minimum (large enough for finger authentication affordance)
- Lock screen top logo/icon area: 80dp/pt top margin to avoid notch/Dynamic Island overlap

**Source:** Existing `OnboardingScreen.kt` (padding 24dp horizontal, 48dp top), `OnboardingView.swift` (padding 32 top, 24 horizontal). Touch target minimum from D-24 (PIN/password is minimum auth on all platforms).

## Typography

All sizes use platform system font. Role maps to platform-specific type scale equivalent.

| Role | Size | Weight | Line Height | Platform Equivalent |
|------|------|--------|-------------|---------------------|
| Body | 14sp/pt | Regular (400) | 1.5 | `bodySmall` / `bodyMedium` (Compose), `.body` (SwiftUI), `14.0` (iced) |
| Label | 16sp/pt | Regular (400) | 1.5 | `bodyMedium` / `labelMedium` (Compose), `.callout` (SwiftUI), `16.0` (iced) |
| Heading | 20sp/pt | SemiBold (600) | 1.2 | `headlineSmall` (Compose), `.title2` (SwiftUI), `20.0` bold (iced) |
| Display | 28sp/pt | Bold (700) | 1.1 | `headlineLarge` (Compose), `.title` (SwiftUI), `28.0` bold (iced) |

Notes:
- Only 2 weights in practice: Regular (400) for body/label, SemiBold/Bold (600+) for headings and primary CTAs
- Error messages use Body (14sp/pt) at Regular (400) in destructive color — no extra weight
- PIN digit display uses Display (28sp/pt) Bold — large enough to count digits at a glance
- "X failed attempts" warning uses Label (16sp/pt) Regular in warning/destructive color

**Source:** Existing `OnboardingScreen.kt` uses `headlineLarge`/`headlineSmall`/`bodyMedium`/`bodySmall` + `FontWeight.Bold`/`FontWeight.SemiBold`/`FontWeight.Normal`. Established pattern preserved exactly.

## Color

Dual-mode (dark/light) matching existing palette defined in `AppColors.swift`, `Color.kt`, `theme.rs`. All values below are dark mode / light mode pairs.

| Role | Dark Value | Light Value | Usage |
|------|------------|-------------|-------|
| Dominant (60%) | `#1A1A1A` | `#F7F7F7` | Lock screen background, PIN setup screen background, full-screen surfaces |
| Secondary (30%) | `#262626` | `#EDEDED` | PIN digit cell backgrounds, input field backgrounds, card containers |
| Accent (10%) | `#4D9EFF` | `#1A6FD4` | Reserved for specific elements listed below |
| Destructive | `#E53E3E` | `#B71C1C` | Wipe/duress warning text, failed-attempt error messages, "Erase All Data" label |
| Warning | `#FBBF24` | `#7B5800` | "Never lock" option warning text in Settings lock timeout picker |
| Success | `#00C896` | `#008C64` | Biometric success indicator, PIN confirmed indicator |

Accent (`#4D9EFF` / `#1A6FD4`) is reserved for:
1. Primary CTA button fill (Unlock, Set PIN, Continue)
2. Active/focused PIN digit cell border
3. "Use Biometrics" button tint (iOS) / icon tint (Android)
4. Progress indicator in Argon2id KDF computation spinner
5. Lock timeout selected-row checkmark (Settings screen)

Accent is NOT used for: body text, secondary text, destructive actions, warning states, or decorative purposes.

**Source:** `AppColors.swift` (verified existing tokens), `Color.kt` (`DarkAccent`, `DarkDestructive`, etc.), `theme.rs` (`ViewColors` struct, `dark_palette()`/`light_palette()`). All hex values match exactly — no new colors introduced.

## Screen Inventory

New screens required by Phase 28. Each maps to a Rust `Screen` variant.

### Screen 1: Lock Screen (`Screen::Locked`)

**Purpose:** Gates all app content on cold launch and after background timeout (ENC-07, ENC-08, ENC-09).

**Layout (all platforms):**
- Full-screen dominant surface background
- Vertically centered column: app icon (48x48) + app name + unlock controls
- App icon: existing Mango app icon at 48x48dp/pt, no border
- App name: Display (28sp/pt) Bold, textPrimary color, centered
- Tagline: Body (14sp/pt) Regular, textSecondary, centered — "Your data is encrypted and protected"

**Biometric path (iOS/Android, when `biometric_available = true`):**
- Biometric prompt triggers automatically on screen appear (no tap required) — per D-11
- Biometric icon button (64x64dp/pt): system biometric icon (Face ID / fingerprint glyph), accent tint
- Button label below icon: Label (16sp/pt), textSecondary — "Face ID" / "Touch ID" / "Fingerprint"
- Below biometric button: TextButton / text link — "Enter PIN instead" (textSecondary, no accent)

**PIN path (always visible on Desktop; fallback on mobile):**
- PIN input: 6-digit secure field, digits obscured with bullets
- On mobile: numeric keypad rendered natively (iOS: `UIKeyboardTypeNumberPad`, Android: `keyboardType = KeyboardType.NumberPassword`)
- On Desktop: standard text input field with `PasswordVisualTransformation`, max 6 chars
- PIN input container: secondary surface background, 12dp corner radius, lg horizontal padding
- Submit: Primary CTA button (full width) — "Unlock"
- No visible PIN length limit label (length is enforced silently, no counter shown)

**Error state (wrong PIN):**
- Input field shakes (brief horizontal animation — 3 cycles at 8dp amplitude, 100ms each)
- Error text appears below field: Body (14sp/pt), destructive color — "Incorrect PIN. Try again."
- After 5 failed attempts: error text changes to "Too many attempts. Wait 30 seconds." — field disabled for 30s with countdown
- No "X attempts remaining" shown before 5th attempt — per Claude's Discretion (silent retry accepted)

**Duress PIN behavior:**
- Identical to normal PIN entry — no visual difference whatsoever
- On duress PIN match: immediate wipe begins with no dialog, no animation — screen transitions to `Screen::Onboarding` — per D-17

### Screen 2: PIN Setup Screen (Post-Onboarding, First Launch)

**Purpose:** Mandatory PIN/password setup after onboarding completes (ENC-11, D-14). No skip option.

**Layout:**
- Navigation: no back button — this step is mandatory
- Heading: Heading (20sp/pt) SemiBold — "Set Your PIN"
- Body: Body (14sp/pt) Regular, textSecondary — "This PIN protects all your encrypted data. You'll use it every time you open the app."
- PIN entry: 6-digit input, same style as Lock Screen
- Confirm PIN: second 6-digit input field, same style, label "Confirm PIN"
- Mismatch error (on submit): Body (14sp/pt), destructive — "PINs don't match. Try again." Both fields clear.
- Primary CTA: "Set PIN" — disabled until both fields are non-empty and match
- Biometric enrollment section (below PIN fields, iOS/Android only, visible when `biometric_available = true`):
  - Toggle / switch: "Enable Face ID" / "Enable Fingerprint" — off by default
  - Body (14sp/pt), textSecondary — "Biometrics let you unlock faster. Your PIN remains the backup."

**Duress PIN section:**
- Collapsible section header: Label (16sp/pt), textSecondary — "Emergency PIN (Optional)"
- Collapsed by default; tap to expand
- When expanded: Body (14sp/pt), textSecondary description + 6-digit entry field labeled "Emergency PIN"
- Warning text (always visible when field is non-empty): Body (14sp/pt), warning color — "If this PIN is entered, all data is immediately and permanently erased."
- No confirmation dialog will appear — this is the warning.
- Validation: duress PIN must differ from real PIN. If identical on submit: inline error "Emergency PIN must differ from your main PIN."

### Screen 3: Lock Timeout Settings Entry (Settings screen addition)

**Purpose:** Configurable lock timeout per ENC-13, D-13. Added to existing Settings screen.

**Placement:** New row in the existing Settings screen (follows Phase 24/26 pattern — grouped sections). Section: SECURITY (new section, below existing sections).

**Row pattern:** Tappable summary row: label "Lock After" + selected value on right + chevron
- Label: Label (16sp/pt) Regular, textPrimary
- Value: Label (16sp/pt) Regular, textSecondary — e.g. "5 minutes"

**Picker (on tap — platform-native picker presentation):**
- iOS: NavigationLink to sub-screen (matches Phase 26 pattern) with radio-style checkmark rows
- Android: same-screen list with radio buttons (matches existing settings pattern)
- Desktop: inline picker with radio-style list items

**Options (in order):**
1. "Immediately" — lock when app goes to background
2. "1 minute"
3. "5 minutes" ← default, pre-selected
4. "15 minutes"
5. "Never" — with warning inline: "Not recommended. Your data will be accessible without authentication." (Body 14sp/pt, warning color)

## Interaction Contracts

### PIN Digit Cell Style (all platforms)

| State | Background | Border | Text |
|-------|------------|--------|------|
| Empty | Secondary surface | 1dp/1pt border, muted (#8C8C8C dark / #737373 light) | — |
| Focused (active input position) | Secondary surface | 2dp/2pt accent border | cursor |
| Filled | Secondary surface | 1dp/1pt muted border | bullet • (obscured) |
| Error | Secondary surface | 2dp/2pt destructive border | bullet • |

### Biometric Auto-Prompt

On `Screen::Locked` appear (iOS/Android only, `biometric_available = true`):
- Trigger biometric prompt immediately — no tap needed
- If biometric succeeds: navigate to previous screen with no animation pause
- If biometric fails or is cancelled: show PIN entry UI (field, submit button, "Enter PIN" is already visible below)
- Never re-trigger biometric automatically after user dismisses — manual tap on biometric icon only

### KDF Loading State (Argon2id)

During Argon2id key derivation (~0.5s on modern phones):
- PIN submit button replaced by `CircularProgressIndicator` (Android) / `ProgressView` (iOS) / iced spinner (Desktop)
- Progress indicator: accent color, 20dp/pt size
- Text beside spinner: Label (16sp/pt), textSecondary — "Unlocking..."
- PIN field disabled during KDF
- No timeout on KDF — wait for completion

### Data Wipe (Duress PIN)

No UI contract — wipe happens silently. App transitions directly to `Screen::Onboarding` first step.

## Accessibility Contract

These apply on all platforms. They extend WCAG 2.1 AA compliance already maintained in existing screens.

- All interactive elements meet 44x44dp/pt minimum touch target (enforced via existing patterns)
- PIN digit cells: each is 52x64dp/pt — exceeds minimum
- Error messages are announced by screen reader immediately on appearance (no delay)
- Biometric icon button: accessibility label = "Unlock with Face ID" / "Unlock with Touch ID" / "Unlock with Fingerprint"
- "Enter PIN instead" link: accessibility label = "Enter PIN to unlock"
- KDF spinner: accessibility label = "Unlocking, please wait"
- Duress PIN field: accessibility label = "Emergency PIN — entering this PIN will erase all data" (VoiceOver/TalkBack)
- Lock screen background must not use system wallpaper bleed (full opaque surface only — privacy)

## Platform Notes

These capture platform-specific implementation differences for executor reference.

### iOS (SwiftUI)

- `LAContext.evaluatePolicy(.deviceOwnerAuthenticationWithBiometrics)` called on `LockScreen.onAppear`
- PIN input: `SecureField` with `keyboardType(.numberPad)`, `maxLength(6)` enforced in `onChange`
- Shake animation: custom `ViewModifier` with `withAnimation(.linear(duration: 0.1).repeatCount(3))`
- Biometric icon: SF Symbol `"faceid"` or `"touchid"` (detected at runtime from `LABiometryType`)
- NavigationBarHidden: true on LockScreen and PinSetupScreen (matches OnboardingView pattern)

### Android (Jetpack Compose + Material3)

- `BiometricPrompt` with `PromptInfo` triggered in `LaunchedEffect(Unit)` on LockScreen composition
- PIN input: `OutlinedTextField` with `keyboardOptions = KeyboardOptions(keyboardType = KeyboardType.NumberPassword)`, `visualTransformation = PasswordVisualTransformation()`, max 6 chars
- Shake animation: `Animatable(0f)` with `animateTo` oscillation
- Biometric icon: `Icons.Filled.Fingerprint` or system-appropriate icon
- CountDownLatch pattern (per D-22) for bridging BiometricPrompt callback to actor thread

### Desktop (iced)

- PIN input: `text_input` with `password()` mode, max 6 chars enforced in `Message::PinChanged`
- No biometric on Desktop (D-23) — PIN-only, no biometric section rendered
- macOS Touch ID via `keyring` is opportunistic (no UI affordance — keyring handles it transparently)
- Lock screen: `center()` layout with `column` of icon + name + pin input + button
- Settings lock timeout: inline `column` of radio-style rows (matches existing settings pattern from Phase 26)
