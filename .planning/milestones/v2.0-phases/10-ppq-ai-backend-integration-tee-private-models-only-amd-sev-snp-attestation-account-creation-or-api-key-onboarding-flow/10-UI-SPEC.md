| Token | Value | Usage |

**Source:** Measured from existing OnboardingView.swift and AttestationBadgeView.swift padding values. Preset row values corrected to grid-aligned multiples of 4.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 17pt / bodyMedium (14sp) | Regular (400) | 1.5 |
| Label / Caption | 12pt / labelSmall–bodySmall (11–12sp) | Regular (400) | 1.4 |
| Secondary label | 15pt / bodySmall–titleSmall (13–14sp) | Regular (400) | 1.4 |
| Heading | 20pt / headlineSmall (24sp) | Semibold (600) | 1.2 |

**Note on Secondary label:** Secondary label is a smaller supporting text role (15pt), not a section heading — sits below Body (17pt) in visual size. Use for provider description lines, API key field footnotes, and attestation detail captions. Do not use for section titles.

**Source:** Derived from SwiftUI `.body`, `.caption`, `.subheadline`, `.title2` and Android `MaterialTheme.typography` scale observed in OnboardingScreen.kt and SettingsView.swift. Only 4 roles declared per contract.

## Component Inventory

### 1. PPQ.AI Provider Preset Row (onboarding + settings)

Reuses the existing `presetRow` pattern from OnboardingView.swift and `disabledRow`/`enabledRow` from SettingsView.swift.

**Unselected state:**
- Background: secondary system background
- Border: none
- Provider name: body weight regular, primary color
- Description text below name: caption, secondary color — "AMD SEV-SNP · Private TEE models"
- TEE type pill (right): caption, secondary color — "AMD SEV-SNP"
- No checkmark

**Selected state:**
- Background: accent.opacity(0.1)
- Border: accent color, 1.5pt stroke, cornerRadius 8
- Provider name: body weight semibold, accent color
- TEE type pill (right): accent color
- Checkmark icon trailing edge: `checkmark.circle.fill` (iOS) / `CheckCircle` filled (Android), accent color

**Interaction:** Tap to select. Single-select among provider cards. Immediately activates API key input field below.

### 2. API Key Entry Field

Pattern: SecureField with rounded border (iOS) / OutlinedTextField with PasswordVisualTransformation (Android).

- Label: "PPQ.AI API Key"
- Placeholder: "sk-..."
- Keyboard: default, no autocorrect, no autocapitalization
- Validation: non-empty check before enabling CTA; trim whitespace on submit
- Error display: caption text in destructive red below the field, shown after failed validation

**Note:** No in-app account creation UI. PPQ.AI account creation is web-only (ppq.ai website). The app only accepts an API key. Link "Get an API key at ppq.ai" shown as tappable footnote beneath the field, opens Safari/external browser.

### 3. "Get an API key at ppq.ai" Link

- Style: `.subheadline` / `bodySmall`, accent color (tappable)
- Placement: directly below API key SecureField
- Action: `openURL("https://ppq.ai")` — opens default browser, does not navigate in-app
- Accessibility label: "Open PPQ.AI website to get an API key"

### 4. Validate & Continue CTA

- iOS: `.borderedProminent`, `.controlSize(.large)`, accent tint
- Android: `Button(modifier = Modifier.fillMaxWidth())`
- Disabled state: when provider not selected OR api key field is empty/whitespace-only
- Loading state: replace button with spinner row — `ProgressView()` + "Validating..." secondary-label text (iOS) / `CircularProgressIndicator` 20dp + "Validating..." bodySmall (Android)

### 5. AMD SEV-SNP Attestation Badge

Reuses `AttestationBadgeView` (iOS) and its Android equivalent.

**New requirement:** `teeTypeLabel()` helper must include an `AmdSevSnp` arm:
- Display string: "AMD SEV-SNP"
- Used in: attestation verified banner ("VERIFIED — AMD SEV-SNP"), settings row TEE type caption

**Badge states (unchanged from existing contract):**

| Status | Icon | Foreground | Background | Border |
|--------|------|-----------|-----------|--------|
| verified | checkmark.shield.fill | #4ADE80 | #1A3A1A | #2E7A2E |
| unverified | questionmark.circle | #9BA3AB | #292929 | #545454 |
| expired | clock.fill | #F9BF24 | #292919 | #7A6B19 |
| failed | exclamationmark.triangle.fill | #F87070 | #3A1A1A | #7A1A1A |

Tapping the badge opens `AttestationDetailSheet` (half-sheet, `.presentationDetents([.medium])`).

**Detail sheet copy for PPQ.AI verified state:**
"This conversation is routed to a PPQ.AI Private TEE model. AMD SEV-SNP hardware attestation has been independently verified by this app — the model runs inside a sealed CPU enclave that prevents the server operator from accessing your data."

### 6. Model Picker — TEE/Private Model Distinction

The existing `ModelPickerView` shows all backend models in a flat menu. For PPQ.AI, TEE/private models must be visually distinguished from non-TEE models.

**Rule:** PPQ.AI Phase 10 scope is TEE models only. No non-TEE models will be registered for the PPQ.AI backend in the initial integration. The model list for the PPQ.AI backend in `known_provider_presets()` will contain only the 5 private TEE models:
- `kimi-k2.5` → display "Kimi K2.5 (Private)"
- `deepseek-r1` → display "DeepSeek R1 (Private)"
- `gpt-oss-120b` → display "GPT-OSS 120B (Private)"
- `llama-3.3-70b` → display "Llama 3.3 70B (Private)"
- `qwen3-vl-30b` → display "Qwen3-VL 30B (Private)"

Model display name format: `{ModelName} (Private)` — the "(Private)" suffix signals TEE-backed inference to the user without requiring a separate icon or badge in the picker menu.

**Interaction:** No change to picker interaction. Menu appears on tap. Checkmark on currently selected model. Accessibility label includes "(Private)" suffix.

### 7. TEE Type Enum Extension

The `TeeType` enum must add `AmdSevSnp`. This affects:
- iOS: `teeTypeLabel()` in OnboardingView.swift and SettingsView.swift
- Android: `teeTypeLabel()` in OnboardingScreen.kt
- Rust: `TeeType` enum in `rust/src/llm/backend.rs` and attestation dispatch in `task.rs`
- Settings advanced form: Picker must add "AMD SEV-SNP" option with tag `"AmdSevSnp"`

**Display string for all platforms:** "AMD SEV-SNP"

## Interaction Flows

### Flow A: First-time onboarding with PPQ.AI

1. User reaches Step 2 (Backend Setup) of the existing 4-step onboarding wizard
2. User sees PPQ.AI in the provider preset list alongside existing providers (Tinfoil, etc.)
3. User taps PPQ.AI row — row highlights with accent border, checkmark appears

**Focal point — Step 2:** Primary visual anchor is the selected provider preset card (accent border + checkmark). Secondary anchor is the Validate & Continue CTA.

4. TEE type label "AMD SEV-SNP" shows on the right of the row
5. Below the preset list, the API key SecureField activates
6. Below the field, tappable footnote: "Get an API key at ppq.ai"
7. User pastes key → taps "Validate & Continue"
8. Button replaced with spinner + "Validating..."
9. On success → proceeds to Step 3 (Attestation Demo) — attestation runs automatically, showing "AMD SEV-SNP" in the verified banner
10. On failure → error text appears below field: "Could not connect to PPQ.AI. Check your API key and try again."

### Flow B: Adding PPQ.AI from Settings

1. User opens Settings → Providers section
2. PPQ.AI row shown in disabled state (not yet enabled)
3. Row shows name "PPQ.AI", description "AMD SEV-SNP · Private TEE models", TEE caption "AMD SEV-SNP"
4. SecureField "API Key" inline in the row
5. Footnote link "Get an API key at ppq.ai" below the field
6. "Enable PPQ.AI" button (`.borderedProminent`, `.controlSize(.small)`, accent tint)
7. On success → row transitions to enabled state, showing health badge + attestation status capsule

### Flow C: PPQ.AI attestation re-check

No new UI needed. Existing attestation badge in chat header handles all states. Detail sheet copy updated for AMD SEV-SNP (see Section 5 above).

## Implementation Notes for Executor

### New TeeType variant

Add `AmdSevSnp` to the `TeeType` enum in `rust/src/llm/backend.rs`:
```
AmdSevSnp,
```

Update `parse_tee_type()` in `rust/src/lib.rs`:
```
"AmdSevSnp" => llm::TeeType::AmdSevSnp,
```

Update attestation dispatch in `attestation/task.rs` to route `TeeType::AmdSevSnp` to the SEV-SNP verification path (already implemented in the existing `verify_sev_snp_report` function; the dispatch switch just needs the new arm).

### New provider preset

Add to `known_provider_presets()` in `rust/src/llm/backend.rs`:
```
ProviderPreset {
    id: "ppq-ai".into(),
    name: "PPQ.AI".into(),
    base_url: "https://api.ppq.ai/v1/".into(),
    tee_type: TeeType::AmdSevSnp,
    description: "AMD SEV-SNP · Private TEE models".into(),
},
```

### TEE type label update (all platforms)

iOS — add to `teeTypeLabel()` in OnboardingView.swift and SettingsView.swift:
```swift
case .amdSevSnp: return "AMD SEV-SNP"
```

Android — add to `teeTypeLabel()` in OnboardingScreen.kt:
```kotlin
TeeType.AMD_SEV_SNP -> "AMD SEV-SNP"
```

Also update the Advanced Settings Picker in SettingsView.swift:
```swift
Text("AMD SEV-SNP").tag("AmdSevSnp")
```

### Model list for PPQ.AI preset

The `ProviderPreset` struct does not currently carry a models list (models are fetched post-auth). For PPQ.AI, the models field on `BackendConfig` will be populated after the API key is validated. No hardcoded model list needed in the preset itself.
