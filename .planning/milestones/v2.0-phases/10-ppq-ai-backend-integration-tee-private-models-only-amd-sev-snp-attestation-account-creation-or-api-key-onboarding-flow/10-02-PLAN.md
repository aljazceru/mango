# Plan 10-02 — Transport Kind and TEE Type Extensions

## Goal
Extend core type system to support PPQ private transport and AMD SEV-SNP TEE type.

## Tasks

### Task 1: Add PpqPrivateE2ee to ProviderTransportKind
Add `PpqPrivateE2ee` variant to `ProviderTransportKind` enum in `rust/src/llm/transport.rs`:
- Add variant to enum definition
- Implement `transport_kind()` method to detect PPQ.AI backends
- Implement `openai_api_base()` to return error for PPQ private transport
- Implement `model_list_url()` to delegate to `ppq_private::model_list_url`
- Implement `build_http_client()` to delegate to `ppq_private::build_http_client`
- Add error message explaining PPQ uses provider-specific transport

### Task 2: Add AmdSevSnp to TeeType
Add `AmdSevSnp` variant to `TeeType` enum in `rust/src/llm/backend.rs`:
- Add variant to enum definition
- Update `parse_tee_type()` in `rust/src/lib.rs` to parse "AmdSevSnp"
- Update attestation dispatch to handle `TeeType::AmdSevSnp`

### Task 3: Add PPQ provider preset
Add PPQ.AI to `known_provider_presets()` in `rust/src/llm/backend.rs`:
- ProviderPreset with id "ppq-ai"
- Name "PPQ.AI"
- Base URL "https://api.ppq.ai/private/v1/"
- TEE type `TeeType::AmdSevSnp`
- Description "AMD SEV-SNP · Private TEE models"

### Task 4: Add ProviderKind::Ppq
Add `Ppq` variant to `ProviderKind` enum in `rust/src/llm/backend.rs`:
- Add variant to enum definition
- Update `parse_provider_kind()` to handle "ppq-ai"

## Success Criteria
1. `ProviderTransportKind::PpqPrivateE2ee` exists and is functional
2. `TeeType::AmdSevSnp` exists and parses correctly
3. PPQ.AI preset appears in `known_provider_presets()`
4. `ProviderKind::Ppq` exists and parses correctly
5. All transport methods delegate to ppq_private module correctly
