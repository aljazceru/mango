<objective>
Wire the Data Encryption Key (DEK) from authentication handlers through ActorState to all VectorIndex call sites, so usearch vector index files are actually encrypted at rest -- closing the gap between the AES-256-GCM capability built in Phase 28-03 and its runtime invocation.

Purpose: ENC-02 requires usearch vector index files encrypted with AES-256-GCM using the DEK. Phase 28-03 built the VectorIndex encryption API (save/load with DEK parameter) but every call site passes `None`. This plan wires the real DEK through.

Output: All VectorIndex operations use the DEK from ActorState, encrypted index files written on every save, and DEK zeroed on lock.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-29-01 | Information Disclosure | ActorState.dek after LockApp | mitigate | `actor_state.dek = None` in LockApp triggers `Zeroizing` drop which zeros the 32 bytes in memory. VectorIndex reset to empty fallback. |
| T-29-02 | Information Disclosure | DEK clone in SetupPin/UnlockWithPin | accept | `Zeroizing<[u8; 32]>` clone is safe -- both original and clone are zeroed on drop. Clone is necessary because local `dek` variable is still used for DB open and keychain store. |
| T-29-03 | Information Disclosure | hex::decode output in BiometricResult | mitigate | Intermediate `Vec<u8>` from hex::decode is on the stack and dropped when scope exits. The final `[u8; 32]` is wrapped in `Zeroizing` immediately. The `Vec<u8>` is short-lived (same expression block). |
| T-29-04 | Tampering | Encrypted VectorIndex file modified on disk | accept | Already mitigated by Phase 28-03: AES-256-GCM authentication tag rejects tampered ciphertext on load (decrypt_file returns Err). |
| T-29-05 | Information Disclosure | Unencrypted temp file during save | accept | Already mitigated by Phase 28-03: temp file uses 0600 permissions, deleted immediately after encryption. |
| T-29-06 | Information Disclosure | VectorIndex opened without DEK in Case D startup | mitigate | Fixed by this plan: Case D creates empty in-memory fallback at startup (no disk file access). Real index opened only after DEK is available post-unlock. |
</threat_model>
