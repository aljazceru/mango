# Requirements: Confidential App

**Defined:** 2026-03-23
**Core Value:** Every inference request is provably confidential -- verified via remote attestation, all data stays local

## v1 Requirements

Requirements for initial release. Each maps to roadmap phases.

### Foundation

- [x] **FOUN-01**: RMP project scaffolded with Cargo workspace, UniFFI bindings, and platform targets (iOS, Android, Desktop/iced)
- [x] **FOUN-02**: Actor model (AppCore) running on dedicated thread with flume channels for action dispatch and state updates
- [x] **FOUN-03**: AppState with monotonic revision, Router for navigation, BusyState for async operations, toast for ephemeral messages
- [x] **FOUN-04**: UniFFI bindings generating Swift, Kotlin, and Rust library targets (cdylib, staticlib, rlib)
- [x] **FOUN-05**: Basic native shell apps on all three platforms (SwiftUI, Jetpack Compose, iced) rendering AppState

### LLM Client

- [x] **LLMC-01**: OpenAI-compatible chat completions client in Rust core supporting streaming (SSE) responses
- [x] **LLMC-02**: Backend configuration system storing provider URL, API key, model list, and TEE type per backend
- [x] **LLMC-03**: Streaming token delivery via InternalEvent into actor loop, accumulating into in-flight message in AppState
- [x] **LLMC-04**: Tinfoil backend integration with correct API base URL and model routing
- [x] **LLMC-05**: Redpill backend integration with correct API base URL and model routing
- [x] **LLMC-06**: Error taxonomy mapping API errors, network failures, and auth errors to human-readable messages in AppState
- [x] **LLMC-07**: Request cancellation (stop generation) that aborts in-flight streaming request

### Attestation

- [x] **ATST-02**: Intel TDX/DCAP quote verification in pure Rust (dcap-qvl crate) -- covers both Tinfoil (TDX) and Redpill (Intel DCAP)
- [x] **ATST-03**: NVIDIA CC attestation via provider JWT/ECDSA signature verification -- covers Tinfoil H100 CC nodes
- [x] **ATST-04**: Attestation result caching in SQLite with TTL-based expiry and OCSP revocation awareness
- [x] **ATST-05**: AttestationStatus enum in AppState (Verified, Unverified, Failed, Expired) per backend
- [x] **ATST-06**: Nonce/TLS channel-binding for attestation requests to prevent replay attacks
- [x] **ATST-07**: Provider attestation API fallback when self-verification is unavailable
- [x] **ATST-08**: Per-conversation attestation status visible to user (trust badge)
- [x] **ATST-09**: Raw attestation report viewable by advanced users

### Backend Routing

- [x] **ROUT-01**: Failover chain -- ordered priority list of backends, automatic fallback on failure
- [x] **ROUT-02**: Smart routing by model availability, latency, and attestation freshness
- [x] **ROUT-03**: Per-conversation backend selection override by user
- [x] **ROUT-04**: Backend health tracking (mark failed, retry with backoff, restore on recovery)
- [x] **ROUT-05**: Provider comparison UI showing TEE type, attestation status, and available models per backend

### Persistence

- [x] **PERS-01**: SQLite database for chat history (conversations, messages, metadata) via rusqlite
- [x] **PERS-02**: Full persistence of conversation state across app restarts
- [x] **PERS-03**: API key storage via platform keychain (iOS Keychain, Android EncryptedSharedPreferences, OS keyring on desktop)
- [x] **PERS-04**: Backend configuration persistence in SQLite
- [x] **PERS-05**: Agent session state persistence in SQLite (survive app restart and resume)

### Chat UI

- [x] **CHAT-01**: Streaming text output rendering tokens as they arrive with no visible lag
- [x] **CHAT-02**: Markdown rendering with code syntax highlighting in all three platforms
- [x] **CHAT-03**: Conversation list / sidebar with title, timestamp, and model indicator
- [x] **CHAT-04**: New conversation creation (one-tap/click)
- [x] **CHAT-05**: Per-message copy button
- [x] **CHAT-06**: Stop generation button that cancels in-flight request
- [x] **CHAT-07**: Conversation rename and delete
- [x] **CHAT-08**: Model selection per conversation from available backend models
- [x] **CHAT-09**: Response regeneration / retry with same prompt
- [x] **CHAT-10**: Edit prior message and re-submit (fork conversation from that point)
- [x] **CHAT-11**: System prompt / custom instructions (per-conversation and global)
- [x] **CHAT-12**: File / document attachment for context (send file contents with message)
- [x] **CHAT-13**: Attestation trust badge displayed per conversation
- [x] **CHAT-14**: Human-readable error messages for API, network, and attestation failures

### Onboarding

- [x] **ONBR-01**: Guided setup wizard on first launch
- [x] **ONBR-02**: Backend selection step (choose from available providers, enter API keys)
- [x] **ONBR-03**: Live attestation verification demonstration during onboarding
- [x] **ONBR-04**: Explanation of TEE concepts and what attestation proves (accessible to non-technical users)
- [x] **ONBR-05**: First chat initiated from onboarding flow

### Local RAG

- [x] **LRAG-01**: On-device embedding computation using ONNX Runtime (CoreML EP on iOS, XNNPACK on Android, CPU/GPU on desktop)
- [x] **LRAG-02**: Document ingestion pipeline (file picker -> text extraction -> chunking)
- [x] **LRAG-03**: Local vector index (usearch HNSW) stored on-device only
- [x] **LRAG-04**: Incremental indexing (add/remove documents without full re-index)
- [x] **LRAG-05**: Context injection -- retrieve relevant chunks and prepend to LLM conversation context
- [x] **LRAG-06**: Document library UI for managing ingested documents
- [x] **LRAG-07**: Support for PDF, plain text, and markdown document formats
- [x] **LRAG-08**: EmbeddingProvider capability bridge (Rust interface, native implementation for NPU access)

### Agent System

- [x] **AGNT-01**: Agent session model as persisted state machine in SQLite
- [x] **AGNT-02**: Tool use / function calling via OpenAI-compatible function calling API
- [x] **AGNT-03**: Multi-turn autonomous execution (run multi-step plans without per-step user approval)
- [x] **AGNT-04**: Background execution on mobile (BGProcessingTask on iOS, WorkManager on Android)
- [x] **AGNT-05**: Agent session list UI showing active, paused, and completed sessions
- [x] **AGNT-06**: Agent can reference RAG documents as context tool
- [x] **AGNT-07**: Agent progress indicators (step-by-step status, not raw streaming)
- [x] **AGNT-08**: User can pause, resume, and cancel agent sessions

### Settings

- [x] **SETT-01**: Settings screen with grouped sections (backends, appearance, behavior, about)
- [x] **SETT-02**: Backend management (add/remove/reorder providers, edit API keys)
- [x] **SETT-03**: Default model and backend selection
- [x] **SETT-04**: No-telemetry guarantee enforced by architecture (no analytics, no crash reporting cloud services)

- **ENHC-02**: Voice input / speech-to-text

- **ENHC-04**: Conversation search across all chat history
- **ENHC-05**: On-chain attestation verification for Redpill and NEAR AI

## Out of Scope

| Feature | Reason |
|---------|--------|
| Cloud sync of documents or chat history | Contradicts core privacy value -- all data stays local in v1 |
| Multi-user / shared workspaces | Single-user personal AI platform; multi-user is a different product |
| Payment / subscription management | Users manage provider billing directly; out of scope |
| Image generation | No TEE backend currently offers it; breaks confidential inference story |
| Browser extension / system-wide AI | Different product category and distribution model |
| Telemetry / analytics | Explicitly excluded by architecture -- no-telemetry guarantee |
| Markdown editor for input | Plain text input; LLMs understand markdown syntax natively |
| Feature flags / A/B testing | Requires telemetry; contradicts privacy guarantee |
