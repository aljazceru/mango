<objective>
Add the ability to fork a chat: duplicate an existing conversation (including its
message history and metadata) into a new independent conversation that the user
can continue in a different direction without affecting the original.

Purpose: A common product pattern (ChatGPT, Claude) — users want to explore an
alternative branch of a conversation without losing the original context. Forking
the whole conversation (not a point-fork) is v1: it matches the simpler, more
common UX and keeps the schema/code trivial. Point-fork (fork from message N) is
a deferred follow-up.

Output:
- A new `persistence::queries::fork_conversation` helper that copies the source
  conversation row (new id, title suffix) and every message row (new ids, same
  order, same content, preserved image_path references) inside a single SQLite
  transaction.
- A new `AppAction::ForkConversation { id }` variant + actor handler that guards
  on db unlocked (warn+continue per the desktop-new-chat-db-panic pattern),
  generates a new uuid, calls the persistence helper, refreshes state, and
  navigates into the new conversation.
- Rust-core integration tests covering the invariants (ordering, metadata
  inheritance, divergence independence, image_path reference-not-copy).
- Desktop (iced) UI wire-up: a **Fork** entry in the same `···` menu row as the
  Export / Docs / Tools / Instructions buttons; pressing it dispatches the
  action.

Scope decision (explicit): per the 260421-tg6 precedent, **this plan ships Rust
core + Desktop only**. iOS and Android are trivial follow-up quick tasks (the
FFI method exists automatically once the AppAction variant is in place; each
platform only needs a menu button that dispatches the action). Point-fork
("fork from this message") is also deferred — the schema here already supports
it (fork_conversation could take an optional `up_to_message_id` later).
</objective>

```rust
pub fn fork_conversation(
    conn: &mut rusqlite::Connection,
    source_id: &str,
    new_id: &str,
    now: i64,
) -> Result<(), PersistenceError>
```

Use `&mut Connection` (not `&Connection`) because we need `conn.transaction()`
for the batch insert. Inside the function:
1. Start a transaction: `let tx = conn.transaction()?;`
2. SELECT the source ConversationRow — reuse the SELECT used by
   `list_conversations` but filter by id. If QueryReturnedNoRows → return
   `PersistenceError::from(rusqlite::Error::QueryReturnedNoRows)`.
3. Build the new ConversationRow with `id: new_id.into()`,
   `title: format!("{} (fork)", source.title)`,
   `created_at: now`, `updated_at: now`, rest copied from source.
4. Insert it: use the same SQL as `insert_conversation` but bind to `&tx`
   instead of `conn`. (Or extract a `insert_conversation_tx(&tx, &row)` helper
   — optional, but preferred for future reuse.)
5. SELECT all source messages via the same SQL as `list_messages`, ordered
   `created_at ASC`.
6. For each source message, generate a new uuid (import/use the same uuid crate
   the rest of the codebase uses — check existing `use uuid::Uuid` sites; the
   `new_uuid()` helper in lib.rs is not visible here, so call
   `uuid::Uuid::new_v4().to_string()` directly or expose a small helper in
   this module).
7. INSERT the new message row with `conversation_id = new_id`,
   `created_at = source_msg.created_at` (preserve original chronology).
8. `tx.commit()?;`
9. `Ok(())`.

Do NOT add ON DELETE CASCADE or change the schema — messages FK still points
at conversations.id; inserts are straightforward.

```rust
AppAction::ForkConversation { id } => {
    // Defense in depth: same guard as NewConversation (desktop-new-chat-db-panic).
    if actor_state.db.is_none() {
        log::warn!(
            "[action] ForkConversation dispatched while DB is locked; ignoring"
        );
        continue;
    }
    let new_id = new_uuid();
    let now = now_secs();
    let result = persistence::queries::fork_conversation(
        actor_state.db.as_mut().expect("db unlocked").conn_mut(),
        &id,
        &new_id,
        now,
    );
    match result {
        Ok(()) => {
            refresh_conversations(&mut actor_state);
            refresh_messages(&mut actor_state, &new_id);
            actor_state.app_state.current_conversation_id = Some(new_id.clone());
            // Inherit tools_enabled from the new row we just persisted.
            actor_state.current_conv_tools_enabled = actor_state
                .app_state
                .conversations
                .iter()
                .find(|c| c.id == new_id)
                .map(|c| c.tools_enabled)
                .unwrap_or(false);
            push_nav_history(&mut actor_state.app_state.router);
            actor_state.app_state.router.current_screen = Screen::Chat {
                conversation_id: new_id,
            };
            sync_visible_streaming_text(&mut actor_state);
        }
        Err(e) => {
            log::warn!("[action] ForkConversation failed: {e}");
            // Non-fatal — UI stays on the source conversation. No state mutation.
        }
    }
}
```
