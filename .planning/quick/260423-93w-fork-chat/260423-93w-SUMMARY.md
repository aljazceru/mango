# Quick 260423-93w: Fork Chat — Summary

## What shipped

**Rust core (platform-agnostic)**

- `persistence::queries::fork_conversation(conn, source_id, new_id, now)` — transactional SQLite helper that:
  - SELECTs the source `ConversationRow`. Returns `PersistenceError` (from `rusqlite::Error::QueryReturnedNoRows`) if the source id does not exist — transaction is rolled back automatically on drop.
  - INSERTs a new conversation row with `title = "{source.title} (fork)"`, copied `model_id` / `backend_id` / `system_prompt` / `tools_enabled`, and `created_at = updated_at = now`.
  - SELECTs every source message in `created_at ASC, id ASC` order and INSERTs a copy with a fresh uuid, `conversation_id = new_id`, and all other columns (role, content, created_at, token_count, image_path) preserved verbatim. `image_path` is a byte-equal string copy — both conversations reference the same encrypted MGO1 file (per quick/260419-ece immutability).
  - Commits on success; implicit rollback on any error.
- `Database::conn_mut() -> &mut rusqlite::Connection` — new accessor so the actor can hand `fork_conversation` a mutable connection for `conn.transaction()`.
- `AppAction::ForkConversation { id: String }` — new variant surfaced to all three platforms via UniFFI.
- Actor handler in `lib.rs` that:
  - Mirrors the `NewConversation` db-locked guard (`if actor_state.db.is_none() { warn!; continue; }`) — desktop-new-chat-db-panic pattern.
  - Generates `new_uuid()`, captures `now_secs()`, calls `fork_conversation`.
  - On success: `refresh_conversations`, `refresh_messages` for the new id, sets `current_conversation_id`, inherits `tools_enabled` from the newly-persisted row, pushes nav history, sets `Screen::Chat { conversation_id: new_id }`, `sync_visible_streaming_text`.
  - On error: warn-log and no state mutation (user stays on the source conversation).

## Deviations from the plan

1. **[Rule 3 — structural]** Tests live at `rust/src/tests/fork_conversation.rs` (inline module under `#[cfg(test)]`) rather than the plan-suggested `rust/tests/fork_conversation_test.rs` integration-test directory. Rationale: the crate has no `rust/tests/` directory — every existing test (persistence, chat, rag, directory_rag, etc.) lives under `rust/src/tests/*.rs` and is wired via `rust/src/tests/mod.rs`. Using the same convention keeps all tests compiling together and matches the pattern every other plan used.

2. **[Rule 3 — API]** Added `Database::conn_mut()` rather than restructuring `fork_conversation` to avoid the transaction. The plan suggested this as one acceptable path; we took it because transactional semantics are the correct primitive for a multi-statement copy (partial-failure safety). A note in the commit message documents the choice.

3. **[Rule 3 — message ordering]** The source-message SELECT uses `ORDER BY created_at ASC, id ASC` (not just `created_at ASC` as `list_messages` does). Rationale: if two seeded messages share a `created_at` (e.g. in tests), we need a deterministic tiebreaker so test assertions are stable. Pure `ORDER BY created_at ASC` (matching `list_messages`) would have worked for production flows, but the tie-broken form is strictly more deterministic and costs nothing.

4. **Export button absent in this worktree base.** The plan referenced an `export_btn` in the conv_menu (from quick/260421-tg6) and told us to render Fork between Export and Instructions. The worktree base commit (81bcb282) does not contain the export UI for Desktop yet — only the core exporter. Fork is therefore rendered between the Tools button and the Instructions section, which is the adjacent slot the plan intent points at. When the Export button eventually lands on Desktop, whichever plan merges it can reorder to `[docs, tools, export, fork, instructions]` as the original plan intended.

5. **Button styling.** Modeled after `docs_btn` / `tools_btn` (the existing neighbors in the conv_menu) rather than the non-existent `export_btn`. Same `Padding::from([4u16, 8])`, same `border.radius = 4.0`, `vc.surface` background, `vc.text_dim` text, muted when disabled. Visually consistent with the surrounding menu.
